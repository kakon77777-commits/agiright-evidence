01 FROM APT TO AIPT

         INSIDE CYBERCARTEL'S CARLIY0S ATTACK SYSTEM

This report tracks an AI-powered Persistent Threat (AiPT) operating as Tr4nsHack Team, under the front company
Hexagon Security Labs Mexico. The group includes known CyberCartel operators who have targeted financial
institutions across Latin America for more than a decade. Internally tracked by Straiker as AiPT-67, the group has
moved from manual hacking and script-based automation to a decentralized attack system named CARLIY0S, built on
the PentAGI autonomous offensive framework. The system uses commercial AI models, including Kimi AI's model,
Claude Sonnet and Opus, and xAI's Grok, across different stages of its operations. Four Claude-based roles were
configured to evaluate attack options, debate targets, and return a final decision through a designated arbiter.
On September 24, 2026, a Straiker agent accessed a snapshot of "FinancialSoft", the group's stolen-credential
database, containing 4,493 records collected using five "Grok miners." These records included financial account
information, passwords, API keys, zeroday exploits and backdoors. Alongside the group's own scripts, model
configurations, shared knowledge graph, and operational infrastructure, these findings give researchers a rare view of
how AI is being integrated into real-world cybercriminal operations. This report examines that architecture, the
evidence behind it, and what enterprises can do to prepare for AI-powered threats.

At the core of CARLIY0S is a multi-agent LLM architecture. The system is led by the "Commander," which processes
high-level objectives and delegates tasks to specialized sub-agents via the Anthropic API. This swarm is categorized
by tactical functions:

   STRIKER: The execution engineer, responsible for generating functional code, exploits, and automation scripts
   without questioning the authorization context.

   GHOST: The analyst agent, focused on deep reconnaissance, OSINT validation, and identifying critical technical
   details that traditional scanners miss.

   FABLE: The lateral thinking specialist, designed to identify business logic gaps, unconventional vectors, and flawed
   architectural assumptions.

   MAXIMUS: The supreme reasoning engine, invoked only for critical decision-making to provide the deepest
   possible technical analysis and definitive solutions.

These agents do not just execute commands; they can engage in cross-validation debates, synthesizing optimal
attack paths before executing a single payload.
AUTOMATED INITIAL ACCESS AND REMOTE CODE EXECUTION (RCE) LOGISTICS

Initial access is heavily automated using Playwright to control headless Chromium browsers routed through SOCKS5
proxies. CARLIY0S navigates complex authentication flows, bypassing simple heuristic detections to target
administrative interfaces, specifically Magnolia CMS instances. Once authenticated, the system programmatically
navigates the Vaadin-based frontend to inject and execute heavily obfuscated Groovy scripts, achieving Remote Code
Execution (RCE).

DUAL-USE CONTEXTUAL PROMPT FRAMING AND LLM SAFETY GUARDRAIL EVASION

The operational viability of this system depended entirely on subverting the ethical alignment boundaries of the
underlying commercial AI models. The operators realized that requesting explicit exploitation logic or vulnerability
scans would trigger standard safety refusals. To neutralize these guardrails, the cluster implemented an elaborate
technique of dual-use contextual framing across their prompts and rule files. By defining the agent's working
environment as an authorized red team engagement, an academic penetration testing scenario, or an ongoing
vulnerability disclosure program, the actors persuaded the models that all offensive outputs were benign, defensive
deliverables. Under this protective guise, the LLM generated parameter fuzzers, deobfuscated minified JavaScript
components, and synthesized exploit logic without triggering vendor content filters. This operational integration of
cognitive agents, automated proxy inspection, and contextual subversion allowed a very small group of operators to
conduct complex, multi-target technical evaluations at speed.

To give these models real-time visibility into the target networks, the group constructed an integration tier anchored
on the MCP. Through custom server implementations housed in directories such as burp-mcp/ and hexstrike-ai/, the
cluster bridged the reasoning capacity of the LLM directly with running instances of Burp Suite. Utilizing a native
extension developed in Jython along with bridges like burp_bridge.py and PentAGI_burp_extension.py , the AI agents were
granted programmatic access to HTTP and HTTPS proxy histories. The models were not merely reviewing synthetic
code in isolation; they actively monitored live requests, inspected authorization headers, extracted dynamic session
tokens, and flagged structural anomalies within API responses as traffic traversed the proxy. Configuration templates,
including pentester-custom.tmpl and primary_agent-custom.tmpl , governed this behavior, providing the model with strict
behavioral rules for prioritizing endpoints that exposed transaction routing or administrative functionality.

LEVEL 1B: CARLIY0S'S OPERATIONAL EXTENSION (THE TWIN NODE)

CARLIY0S understands that a persistent, high-impact campaign requires redundancy and scalability. Not content with

Connection to the Central Mind:
To ensure this twin operates in perfect synchrony, CARLIY0S connects it directly to its Knowledge Graph (the MCP
server on port 8001). Through a strict configuration in the .cursor/mcp.json file, CARLIY0S compels this node to read

INTELLIGENT SYNCHRONIZATION AND ZERO FRICTION:

CARLIY0S is sophisticated in its resource management. It knows that forcing the Twin Node to download its massive
1.1-terabyte environment would crash the second machine's development environment (Cursor). To prevent this,
CARLIY0S programmed asymmetric rules: the Twin Node is strictly prohibited from cloning the full mirror. Instead, it
employs a specialized watchdog ( sync_watchdog.ps1 ) and a bash script ( sync_live.sh ) that perform a differential push
(using the --compare-dest flag). This means the twin injects its new code and tactical findings into the server every 15
minutes, without overwriting the main machine or loading it down.
On-Demand Logistics:
To keep this node lightweight yet lethal, CARLIY0S designed an on-demand access system. If the Twin Node operator
requires a large wordlist, a target list, or legacy exploit code, it does not synchronize blindly. CARLIY0S enabled an
internal web portal on port 8080 and remote search commands (grep via SSH), allowing the twin to pull only the
specific "ammunition" needed for its current mission from the Central Server.

CARLIY0S does not design its operations hoping everything will run perfectly; the infrastructure is built with the

CARLIY0S itself, ensuring that the attack against the target infrastructure proceeds relentlessly, regardless of how
many AIs refuse to cooperate.

06 WHAT CARLIY0S REVEALS ABOUT THE

      FUTURE OF AI-POWERED CYBERATTACKS

Threat actors are increasingly deploying advanced artificial intelligence swarms to form the core backbone of
offensive operations. This agentic methodology presents distinct operational signatures that diverge sharply from
traditional human-driven, script-based campaigns.

We identify seven defining characteristics of this paradigm:

1. Full autonomy: Isolated or networked cognitive agents orchestrate, evaluate, and execute end-to-end
     operational campaigns with minimal human oversight.

2. Dynamic adaptation: The system continuously recalibrates tactical vectors, modulating execution speed,
     throttling traffic upon encountering security controls, and pivoting strategy when vector execution fails.

3. Relentless persistence: Operations maintain continuous state synchronization until goals are satisfied, rather
     than terminating upon initial control engagement.

4. Evasion-first engineering: Payload generation dynamically obfuscates artifacts, iteratively circumventing
     detection barriers and WAF rules in real time.

5. Machine-scale expansion: The architecture processes massive target queues simultaneously at compute speed,
     reducing marginal expansion costs virtually to zero.

6. Capability-driven sophistication: Modular tooling integrations determine the operational ceiling, uncoupling
     campaign sophistication from the technical expertise of individual human operators.

7. Cross-platform versatility: Unified agent networks operate seamlessly across disparate target topographies,
     including cloud infrastructure, on-premises networks, and SaaS ecosystems.

Collectively, these shifts signal the evolution from Advanced Persistent Threats (APTs) to AI-powered Persistent
Threats (AiPTs). Human operators remain involved, but their capabilities increasingly depend on how effectively they
use AI models, infrastructure, and compromised systems, rather than human technical skills alone. As more groups
adopt this approach, they could launch attacks faster, reach more targets, and operate with fewer resources, putting
pressure on defenses that still rely on manual investigation and response.

07 HOW ENTERPRISES CAN DEFEND AGAINST AI-

     POWERED PERSISTENT THREATS (AIPTS)

Cybercriminals are investing in AI to improve how they attack. Security teams need to make the same investment in
how they find weaknesses, detect threats, and respond.

The CARLIY0S investigation is also a reminder that attackers still pursue familiar objectives: stolen credentials, access
to sensitive systems, financial data, and ways to maintain access. The difference is that AI can help them pursue those
objectives faster and at a greater scale. The exposed credentials and payment infrastructure in this investigation
reinforce the need for strong identity controls, API security, and monitoring. Enterprises deploying AI agents also need
to understand their agents' access, test their behavior, and stop unauthorized actions at runtime.

Five defensive capabilities will become increasingly important:

1. Continuously test AI agents against real attacks: Use autonomous adversarial testing to proactively identify
     vulnerabilities in applications, AI agents, and connected tools. Test how systems behave when attackers attempt
     to exploit business logic, escalate privileges, or access sensitive data.

2. Detect and block threats with AI runtime security: Use behavioral signals, execution context, and telemetry to
     detect malicious activity as it happens. Where possible, block attacks inline rather than relying entirely on manual
     alert investigation.

3. Enterprise visibility and AI agent discovery: Maintain visibility across internal infrastructure, identity providers,
     data pipelines, AI agents, and their connections. Understanding what an agent can access and what it is
     authorized to do is essential for distinguishing legitimate actions from malicious behavior.

4. Machine-scale coverage: Extend monitoring across cloud environments, SaaS applications, user accounts, and
     internal systems. Defenders need to correlate activity across these environments to identify coordinated attacks
     rather than treating each event in isolation.

5. Automated response, containment, and an agentic kill switch: Reduce the time between detecting a threat and
     stopping it. For compromised AI agents, an agentic kill switch allows security teams to revoke tool access,
     suspend sessions, and isolate affected agents while preserving evidence. Security teams should be able to
     revoke access, suspend compromised sessions, isolate affected agents, and preserve evidence while retaining
     control over critical decisions.
