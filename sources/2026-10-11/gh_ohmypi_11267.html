Description

When using google-antigravity (Google Cloud Code Assist) or google-gemini-cli, dynamic model discovery exposes four raw Gemini 3.8 Flash endpoint IDs from daily-cloudcode-pa:

  • gemini-3.8-flash-low
  • gemini-3.8-flash-medium
  • gemini-3.8-flash-high
  • gemini-3.8-flash-tiered

Unlike gemini-3.6-flash and gemini-3.7-flash, which are collapsed into a single canonical model with google-level thinking routing, Gemini 3.8 Flash is currently missing from the variant collapse definitions in packages/catalog/src/variant-collapse.ts.

As a consequence:

  1. All four raw endpoints are registered as separate selectable models in the catalog / /model.
  2. Because all Gemini 3.x models enforce mandatory reasoning (reasoning: true, mode: "google-level", efforts: ["minimal", "low", "medium", "high"], requiresEffort: true), every one of the four raw endpoints (including -low, -medium, and -high) still prompts for / expects an explicit thinking level selection, even though the raw endpoints were designed upstream as fixed effort presets.

Steps to Reproduce

  1. Authenticate with google-antigravity (/login google-antigravity).
  2. Run omp models refresh (or restart omp) to fetch dynamic discovery models from Cloud Code Assist.
  3. Run omp models ls google-antigravity or open the model selector (/model).
  4. Observe four separate entries: gemini-3.8-flash-low, gemini-3.8-flash-medium, gemini-3.8-flash-high, and gemini-3.8-flash-tiered.
  5. Select any of them (e.g. gemini-3.8-flash-low); notice that it still has full reasoning enabled and prompts for thinking level configuration (minimal/low/medium/high).

Expected Behavior

Similar to Gemini 3.6 and 3.7 Flash, gemini-3.8-flash should be defined in packages/catalog/src/variant-collapse.ts:

const GEMINI_38_FLASH_FAMILY = geminiLevelFlashFamily("3.8");

and wired into both ANTIGRAVITY_VARIANT_COLLAPSE_TABLE and GEMINI_CLI_VARIANT_COLLAPSE_TABLE.

This will collapse gemini-3.8-flash-{low,medium,high,tiered} into a single canonical gemini-3.8-flash model with gemini-3.8-flash-tiered as an alias and standard effortRouting:

  • minimal -> gemini-3.8-flash-low
  • low -> gemini-3.8-flash-low
  • medium -> gemini-3.8-flash-medium
  • high -> gemini-3.8-flash-high

Error Output

No error output; catalog normalization / variant collapse omission.

    Already handled on main — no per-version entry is needed.

    The premise (a hand-edited packages/catalog/src/variant-collapse.ts with geminiLevelFlashFamily/GEMINI_37_FLASH_FAMILY) describes an architecture that no longer exists. Variant collapse now lives in the KDL policy tree (packages/catalog/src/compat/rules/taxonomy/_collapse.kdl, compiled to rules.json, applied via collapseVariants in src/compat/collapse.ts). Since commit 2243f03707ba ("introduced revision templating to unify definitions", first released in v18.1.4), the Gemini Flash families are defined once as a revision-templated family instead of one entry per version:

    variant-family "google-antigravity" "gemini-{rev}-flash" name="Gemini {rev} Flash" revision=">=3.6" {
	members "gemini-{rev}-flash-low" "gemini-{rev}-flash-medium" "gemini-{rev}-flash-high" "gemini-{rev}-flash-tiered"
	route "minimal" "gemini-{rev}-flash-low"
	route "low" "gemini-{rev}-flash-low"
	route "medium" "gemini-{rev}-flash-medium"
	route "high" "gemini-{rev}-flash-high"
	mode "google-level"
	efforts "minimal" "low" "medium" "high"
	requires-effort #true
}

    The identical template exists for google-gemini-cli. Because it matches any gemini-{rev}-flash with revision >= 3.6, 3.8 (and every future Flash revision) is already collapsed — nothing to add.

    Verified against the current default branch by running collapseVariants on the four raw endpoints:

    $ collapseVariants([gemini-3.8-flash-{low,medium,high,tiered}], provider=google-antigravity)
[
  {
    "id": "gemini-3.8-flash",
    "requestModelId": "gemini-3.8-flash-low",
    "thinking": {
      "mode": "google-level",
      "efforts": ["minimal", "low", "medium", "high"],
      "requiresEffort": true,
      "effortRouting": {
        "minimal": "gemini-3.8-flash-low",
        "low": "gemini-3.8-flash-low",
        "medium": "gemini-3.8-flash-medium",
        "high": "gemini-3.8-flash-high"
      }
    }
  }
]

    That is exactly the requested outcome: a single canonical gemini-3.8-flash, -tiered folded in, standard google-level effort routing.

    You're on v18.1.2, which predates the template (the older per-version definitions hardcoded 3.6/3.7 only). Updating to v18.1.4 or later resolves this. Closing as a duplicate of the collapse-unification work in 2243f03707ba; the -tiered folding specifically tracks back to #10018.
